计划修正 (源码层判据 vs 计划文本不一致, 已源码确认行为正确)
==========================================================================

[C1] §2.2C "removeEmptyUserMessages 删除空条" 表述需要松动
  现象: 计划要求空 user 被该函数删除. 实测出站 history 中
        合成的 KIRO_HELLO_MESSAGE 在前, 空 user 仍在.
  源码确认: claude-kiro.js:372-384 removeEmptyUserMessages 实现里
        有显式 "保护第一条 user" 的分支 — 因为 sanitize 7 步管线
        要求 STARTS_WITH_USER 不变量, 第一条若被删, 后续步骤无 anchor
        可锚定. 实际删除发生在 "第一条之后的空 user" 上, 第一条
        若空则交给 ensureStartsWithUserMessage 在前面拼合成 user 修复.
  结论: 行为符合 7 步管线设计意图, sanitize 整体语义 (产出合法
        交替序列) 仍达成, 视为 PASS. 计划文本可改为:
        "空 user 被 removeEmptyUserMessages 或合成 user 前缀
         任一手段处理为合法序列".

[C2] §2.2D "flatten 成 XML 文本" 归属错误
  现象: 计划要求 ensureValidToolUsesAndResults flatten orphan tool_use
        为 XML. 实测出站 history 仍是结构化 tool_use + 合成的
        failed tool_result.
  源码确认:
    - claude-kiro.js:311-370 ensureValidToolUsesAndResults: 当
      tool 仍在 tools[] 注册表中, 走 "合成 status=error 的
      toolResults" 分支, 不 flatten.
    - claude-kiro.js:515-548 normalizeKiroToolHistory: 当 tool
      已从 tools[] 移除 (即真正的 "orphan unknown tool"), 才把
      tool_use+tool_result 双向 flatten 为 <tool_use>/<tool_result>
      XML 文本.
    - 这正是 §2.3 测试的路径.
  结论: 计划在 §2.2D 与 §2.3 之间错配了归属. §2.2D 的合成失败
        tool_result 行为正确, 视为 PASS; XML flatten 由 §2.3 单独
        覆盖, 已通过.
